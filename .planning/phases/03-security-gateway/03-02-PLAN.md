  <files>docs/security-gateway/opa-policy-enforcement.md</files>
  <action>
Replace the 7-line stub with a full OPA policy enforcement page. Structure:

1. **Enterprise admonition** (standard pattern).

2. **"What is OPA Policy Enforcement?"** (2-3 paragraphs):
   - Frame for security architects who know firewall rules but not OPA: "Open Policy Agent (OPA) is a general-purpose policy engine. loxilb-enterprise integrates OPA as a dynamic L4 firewall rule source — you write policies in Rego (OPA's policy language), and loxilb automatically translates them into dataplane firewall rules."
   - Explain the value: centralized policy management, GitOps-compatible (Rego policies in version control), separation of policy logic from enforcement.
   - Key concept for networking engineers: Rego is like a declarative ACL language. Instead of writing firewall rules directly, you write conditions that generate firewall rules.

3. **OPA Watcher Architecture** (Mermaid diagram):
   ```
   OPA Server (Rego policies) --[HTTP poll every 30s]--> loxilb OPA Watcher
   loxilb OPA Watcher --[diff engine]--> Only changed rules applied
   loxilb OPA Watcher --[normalize]--> FwRuleArg (L4 firewall rules)
   FwRuleArg --[REST API]--> loxilb Dataplane (/netlox/v1/config/firewall)
   ```
   Source: pkg/opa/watcher.go (polling), pkg/opa/fetcher.go (HTTP client), pkg/opa/normalizer.go (Rego → FwRuleArg), pkg/opa/applier.go (REST push to loxilb)

   Explain the circuit breaker: If OPA server is unreachable, the circuit breaker prevents repeated failed requests. States: closed (normal), open (OPA down, skip fetches), half-open (testing recovery). Source: pkg/opa/types.go CircuitBreakerState.

4. **Configuration — OPA Watcher** (REST API with source trace):
   ```json
   // Source: pkg/opa/watcher.go:37-53, swagger.yml:9902-9921
   POST /config/opa/watcher
   {
     "opa_url": "http://opa:8181",
     "policy_path": "loxilb/l4",
     "poll_interval_sec": 30,
     "fail_open": false
   }
   ```
   Document each field:
   - `opa_url`: HTTP endpoint of OPA server (default: none, required)
   - `policy_path`: Rego package path to query (default: "loxilb/l4")
   - `poll_interval_sec`: How often to fetch policies (default: 30)
   - `fail_open`: Whether to allow traffic when OPA is unreachable (default: false = fail-closed)
   - Also document `initial_delay_sec` (default: 10), `loxilb_url`, `state_path` from WatcherConfig

5. **`!!! danger` admonition**: "OPA defaults to **fail-closed** (`fail_open: false`). When OPA is unreachable, no firewall rules are updated and existing rules remain. If the watcher has never successfully fetched policies, **no rules will be installed** and default network behavior applies. Set `fail_open: true` only if availability is more critical than policy enforcement."

6. **Writing Rego Policies for loxilb** section:
   - The Rego package MUST match the `policy_path`. Default: `package loxilb.l4`
   - Show the expected output structure — `firewall_access_rules` array with OPARule fields
   - Source: pkg/opa/types.go:21-27 (OPAPolicyResponse JSON shape)

   Full Rego example (constructed from OPARule struct fields):
   ```rego
   # Source: pkg/opa/watcher.go:33 — defaultOPAPolicy = "loxilb/l4"
   package loxilb.l4

   import future.keywords.in

   # Allow HTTPS from internal network
   firewall_access_rules[rule] {
     rule := {
       "sourceIP": "10.0.0.0/8",
       "destinationIP": "0.0.0.0/0",
       "protocol": 6,
       "minSourcePort": 0,
       "maxSourcePort": 65535,
       "minDestinationPort": 443,
       "maxDestinationPort": 443,
       "action": "allow",
       "preference": 100
     }
   }
   ```

   **`!!! warning` admonition**: "The Rego package declaration must match `policy_path`. If your policy uses `package policy.firewall` but `policy_path` is `loxilb/l4`, the watcher will fetch empty results and silently remove all firewall rules."

7. **OPARule Field Reference** table:

| Field | Type | Description | Example |
|-------|------|-------------|---------|
| sourceIP | string (CIDR) | Source IP range | "10.0.0.0/8" |
| destinationIP | string (CIDR) | Destination IP range | "192.168.1.100/32" |
| protocol | int | IP protocol (6=TCP, 17=UDP) | 6 |
| minSourcePort | int | Source port range start | 0 |
| maxSourcePort | int | Source port range end | 65535 |
| minDestinationPort | int | Destination port range start | 80 |
| maxDestinationPort | int | Destination port range end | 80 |
| action | string | "allow" or "deny" | "allow" |
| preference | int | Rule priority (higher = processed first) | 100 |

   Source: pkg/opa/types.go:21-27

8. **Monitoring and Troubleshooting**:
   - GET /config/opa/watcher returns WatcherStatus with last_sync, rules_count, circuit_breaker_state
   - DELETE /config/opa/watcher removes the watcher
   - Common issue: rules disappearing = policy_path mismatch (see warning above)

9. **See Also**: Rate Limiting, IP Filtering, Security Gateway Overview
